5. Does IMU need to be rotated to world frame before getting to this script?

No. In the current design, the IMU acceleration should come into this script in the body/IMU frame as:

imu_sample.accel_body = [ax ay az];

Then this script rotates it to the world frame inside:

getWorldAcceleration()

using:

imu_sample.orientation = [roll pitch yaw];

So the reader does not need to rotate acceleration to world frame before passing it to ImuFusionFilter.

But the reader does need to make sure the IMU axes are standardized first.

So the split should be:

ReadCustomPcb / ReadLimo / ReadBebop:
    fix IMU axis mapping and signs
    output accel_body in expected body-frame convention
    output orientation in degrees

ImuFusionFilter:
    rotate accel_body from body frame to world frame
    remove gravity if needed
    integrate acceleration

So to confirm:

Do not rotate to world frame before this script.
Do fix axis/sign mapping before this script.
